# 体渲染与剖面的一致性

## 两条路径共用的部分

- 同一份数据纹理：每个变量只上传一次，存成半精度的 `Data3DTexture`（`FieldTextures.scalar`）。体渲染、高度切片、经纬剖面、折线剖面、框选层叠都绑定这一份。
- 同一套采样：都用 `localToTex` 把根节点局部坐标（km）换算成纹理坐标，第 i 层在 `(i + 0.5) * dz`，都走硬件三线性插值。垂直夸张只作用在 `root.scale.y` 上，着色器里换算回真实高度，所以两边的高度对得上。
- 同一个值域：`自动范围` 读 manifest 里的 `display_range`（例如 icing_index 是 0–1），不随时次变化。

## 之前对不上的原因

1. **透明度规则不同（主因）**：体渲染跳过归一化值低于阈值（默认 0.2）的体素，再沿视线累积 `smoothstep(阈值, 1, n)` 的不透明度，低值看不见，亮色由高值主导。剖面则把每个像素都画成 `colormap(t)`，不透明度是常数。icing_index 这类稀疏场大部分是 0，用 Magma 时低端是黑色，于是剖面成了一大片不透明的黑；不透明度为 1 时还会写深度，最上面一层把下面全挡住。
2. **色带不一定相同**：体渲染用变量的默认色带（发散色带会换成 magma），剖面色带由用户自己选。

## 现在的规则

- 剖面新增「低值透明」：归一化值 t 低于阈值时完全透明，往上 25% 的区间内用 `smoothstep` 渐显，起点和体渲染阈值的思路一致。高度切片、经纬剖面、折线剖面、框选层叠和体渲染里合成的剖面面片都用同一个 `lowAlphaFactor`。开启后剖面不写深度，下面的层能透出来。
- 默认值按变量来：稀疏的非负场（icing_index、icing_accum、cloud、cloud_low、precip、risk_level；或者至少一半样本落在值域最低 2% 以内的非负场）默认开启，风速、温度这类连续场默认关闭。切换变量时重置为该变量的默认值，色带也重置为变量默认色带。阈值滑块范围 0–60%，默认 15%。
- 体渲染和剖面显示同一个变量时，体渲染直接沿用剖面的色带和值域。
- 调试：`__atmosApi.debugCompare(name, ix, iy, k)` 对同一个体素分别按体渲染和剖面的映射算出 t 和 RGB，CPU 端查的是同一张 256 色查找表，返回结果里带 `match` 字段；截图脚本里的 `v6_8-*` 视角会把这个结果打到输出 JSON 里。

## 剩下的差异

体渲染沿视线积分，颜色亮度和路径长度、步长、不透明度滑块都有关；剖面是在某一个面上的单次取样。同一个体素映射出的颜色相同，但体渲染画面上的观感（例如“火焰状”的柱）会比单层剖面更亮、更连成片。
